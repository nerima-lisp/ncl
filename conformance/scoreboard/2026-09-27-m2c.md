## ansi-test

doit.lsp から init.lisp、gclload1.lsp、rt-package.lsp / rt.lsp を経由する入口です。gclload1.lsp:59 の (compile-and-load "rt.lsp") に至る前後で REGRESSION-TEST package が登録されず、regression-test:do-tests の参照時に停止しました。

実測は exit 1、stdout 0 bytes、stderr ncl: read error: PackageNotFound("REGRESSION-TEST")、非空の選択項目数 0 です。章実行前の停止なので passed/failed/unexecuted は算出不能であり、0 passed とは扱いません。

## 再現コマンド

release build:

~~~sh
$W build --release -p ncl
~~~

ansi-test:

~~~sh
cd <ansi-test-checkout>
../target/release/ncl --load doit.lsp < /dev/null
~~~

cl-bench の一括入口:

~~~sh
cd <cl-bench-checkout>
../target/release/ncl --eval '(progn (load "package.lisp") (load "cl-bench.lisp") (load "tests.lisp") (funcall (read-from-string "cl-bench:bench-run")))'
~~~

$W は指定された ncl-cargo.sh wrapper、<...-checkout> は固定 commit の一時 checkout を表します。

## 数字を伸ばすのに効く順の実装項目

以下は失敗地点からの優先順位です。1--3 は計測を開始可能にする blocker、4 以降は計測開始後に数字を増やす項目です。

1. reader の package marker 解決を、defpackage 実行前の CL-BENCH / REGRESSION-TEST 参照で失敗しないようにする。
2. constant requires a runtime table に至る constant loading と runtime table の初期化順を直す。
3. load / compile-and-load の ansi-test 起動経路を完成させ、rt.lsp と rt-package.lsp を登録できるようにする。
4. defpackage と package nickname/use/export の初期化を ansi-test と cl-bench の両方で通す。
5. defmacro と macro expansion を cl-bench の defbench 登録まで通す。
6. handler-case と condition/restart の基本経路を ansi-test の runner まで通す。
7. 数値の fixnum 算術・比較・再帰呼び出しを完成させ、fib、tak、ackermann を最初の速度指標にする。
8. cons/list、破壊的更新、simple-vector を通し、Gabriel 系ベンチを増やす。
9. sequence/string/hash-table の基本操作を通し、配列・文字列・探索系ベンチを増やす。
10. CLOS、stream、format、file I/O を順に通し、残りの cl-bench と ansi-test の章を広げる。

この計測では本体コードは変更していません。ハーネスの timeout/crash 分類は既存の分類を使い、今回の失敗はいずれも process failure として観測できました。
