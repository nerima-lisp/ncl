# Compatibility

NCL has a production-oriented Rust runtime. It is a bounded Common
Lisp-oriented implementation, not an implementation-compatible runtime. The
table below describes the runtime feature boundary.

| Area | Implemented surface | Current boundary |
| --- | --- | --- |
| Reader | Symbols, keywords, numbers, strings, characters, lists, dotted lists, vectors, quote prefixes, line comments, nested block comments, discarded forms, and bounded <code>#+</code>/<code>#-</code> reader conditionals with <code>and</code>/<code>or</code>/<code>not</code>. | Reader conditionals use the fixed default <code>NCL</code>/<code>COMMON-LISP</code> feature set; custom feature sets are available through the syntax API. Reader depth and syntax coverage are bounded, and an unquote outside quasiquote is rejected. |
| Evaluation | Conditional forms, sequencing, lexical bindings, local functions, definitions, iteration, bounded <code>LOOP</code> clauses including list/vector/hash-table traversal and accumulation, <code>DO-SYMBOLS</code>/<code>DO-EXTERNAL-SYMBOLS</code>/<code>DO-ALL-SYMBOLS</code>, <code>WITH-PACKAGE-ITERATOR</code>, <code>MAPHASH</code>, <code>WITH-HASH-TABLE-ITERATOR</code>, macros with escaped <code>&KEY</code> identity, <code>destructuring-bind</code> with escaped keyword identity, packages, bounded global <code>SPECIAL</code> declarations through <code>DECLAIM</code>/<code>PROCLAIM</code>, local <code>DECLARE (SPECIAL ...)</code> scopes in <code>LET</code>/<code>LOCALLY</code>, generalized places, structures, classes, generic functions, methods, bounded <code>LOAD</code> keyword handling, and bounded load-time/multiple-value forms. | <code>LOAD</code> evaluates UTF-8 source through the runtime evaluator; <code>:verbose</code> and <code>:print</code> are accepted but have no output effect, and pathname/version semantics are partial. The supported loop, package-symbol, and hash-table iteration subset does not establish complete iteration or macro semantics; package symbol identity and mutation behavior are bounded by the runtime package model. Local declaration semantics outside the supported <code>LET</code>/<code>LOCALLY</code> scope path and several object-system and standard semantic details remain partial. |
| Functions | Builtins, closures, separate local function bindings, ordinary lambda lists, <code>funcall</code>, <code>apply</code>, and mapping operations. | The lambda-list and function protocol do not cover every Common Lisp edge case. |
| Multiple values | Creation, binding, calls, list conversion, sequencing, assignment, and multiple-value status results. | Interactions with unsupported standard facilities are outside the tested surface. |
| Conditions | Formatted <code>error</code>/<code>signal</code>/<code>warn</code>/<code>cerror</code> signaling with <code>SIMPLE-CONDITION</code> metadata, bounded <code>define-condition</code> inheritance with slot initargs/initforms and reader/accessor/writer functions, basic <code>make-condition</code> construction, condition type predicates, <code>simple-condition-format-control</code>/<code>simple-condition-format-arguments</code>, <code>assert</code> failure signaling with <code>CONTINUE</code>-based test retry, <code>ccase</code>/<code>ctypecase</code> type-error retry with <code>STORE-VALUE</code>/<code>USE-VALUE</code>, <code>check-type</code> replacement and place storage, failure-time place/datum/argument evaluation, <code>ignore-errors</code>, <code>handler-case</code> including bounded <code>:no-error</code> success clauses, dynamic <code>handler-bind</code>, bounded <code>restart-bind</code>/<code>restart-case</code>, restart objects with <code>compute-restarts</code>/<code>find-restart</code>/<code>restart-name</code>, condition associations with <code>with-condition-restarts</code>, simple restarts, and cleanup with <code>unwind-protect</code>. | The full condition hierarchy, report functions, debugger-editable generalized references for <code>assert</code> places, standard condition constructors/accessors, and remaining handler/restart protocol details are incomplete. |
| Packages | Package definition and lifecycle with <code>make-package</code>, <code>delete-package</code>, and <code>rename-package</code>, use lists, exports, qualification, interning, lookup, package predicates, bounded package metadata queries for nicknames, shadowing symbols, and users, plus bounded <code>DO-SYMBOLS</code>/<code>DO-EXTERNAL-SYMBOLS</code>/<code>DO-ALL-SYMBOLS</code> and <code>WITH-PACKAGE-ITERATOR</code> traversal. | Package mutation beyond the supported use/export/shadow model, complete symbol identity/shadowing semantics, duplicate/conflict behavior across multiple iterator packages, and full standard package iteration behavior are not complete. |
| Numbers | Integers, floats, rationals, bounded complex construction with <code>complex</code>, projections with <code>realpart</code>/<code>imagpart</code>, <code>conjugate</code>, <code>phase</code>, numeric type relationships, arithmetic, comparisons, rounding, integer operations, rational accessors, transcendental functions, bounded numeric and sequence <code>COERCE</code> conversions, radix integer literals (<code>#b</code>/<code>#o</code>/<code>#x</code>/<code>#NrDDD</code>), Common Lisp float exponent markers (<code>s</code>/<code>f</code>/<code>d</code>/<code>l</code>), and <code>random</code>/<code>make-random-state</code>/<code>random-state-p</code> backed by a <code>xorshift64*</code> generator. Mixed real/complex <code>+</code>, <code>-</code>, <code>*</code>, <code>/</code>, and <code>=</code> are supported. | The bounded reader accepts <code>#C</code> with exactly two component forms and lowers it to <code>complex</code>. Float type aliases share one f64-backed representation. Exact arithmetic (<code>+</code>, <code>-</code>, <code>*</code>, <code>/</code>, <code>expt</code>, <code>sqrt</code>, <code>abs</code>, <code>signum</code>) promotes to an arbitrary-precision integer on <code>i64</code> overflow, and large integer literals parse as such with no size limit of their own. A single exact-arithmetic computation whose result would exceed 100,000 decimal digits reports numeric overflow rather than growing unbounded; <code>sqrt</code> applies that same 100,000-digit bound to its operand instead, since a square root only ever shrinks its input. The complete numeric tower and the remaining coercion/printing rules are not implemented. <code>random-state</code> objects are not printable/readable via <code>#S</code>-style syntax and <code>*random-state*</code> is not yet a bound special variable. |
| Strings and streams | Character/string operations, string and file streams, bounded line and character I/O, <code>WRITE-STRING</code>/<code>WRITE-LINE</code> <code>:START</code>/<code>:END</code> ranges, file opening/closing, <code>WITH-OPEN-STREAM</code>/<code>WITH-OPEN-FILE</code>, <code>WITH-INPUT-FROM-STRING</code> with <code>:START</code>/<code>:END</code>/<code>:INDEX</code>, <code>WITH-OUTPUT-TO-STRING</code> with the standard <code>NIL</code>/<code>:ELEMENT-TYPE</code> form and mutable fill-pointer string destinations, <code>FILE-POSITION</code> query/repositioning, <code>FILE-LENGTH</code> character-length queries, <code>STREAM-ELEMENT-TYPE</code>, <code>STREAM-EXTERNAL-FORMAT</code>, <code>OPEN-STREAM-P</code>, <code>FORCE-OUTPUT</code>,
<code>FINISH-OUTPUT</code>/<code>CLEAR-OUTPUT</code>, <code>LISTEN</code>/<code>READ-CHAR-NO-HANG</code>/<code>CLEAR-INPUT</code> for modeled character streams, <code>WRITE-SEQUENCE</code> for character sequences, duplex <code>:io</code> streams, adjustable string designators, and formatted output. | The general stream protocol, binary streams, full file-option/version semantics, byte-oriented position/length semantics for multibyte external formats, precise buffered-output discard semantics, and the remaining <code>format</code> directives are incomplete; stream resource-management options remain bounded. |
| Arrays and tables | Simple and multidimensional arrays plus hash tables with <code>eq</code>, <code>eql</code>, <code>equal</code>, and <code>equalp</code> tests; bounded rank-1 fill-pointer/adjustable vectors with <code>:fill-pointer</code>, <code>:adjustable</code>, <code>fill-pointer</code>, <code>vector-push</code>, <code>vector-push-extend</code>, and <code>adjust-array</code>; bounded <code>T</code>, <code>BIT</code>, <code>CHARACTER</code>, <code>BASE-CHAR</code>, <code>FIXNUM</code>, <code>SINGLE-FLOAT</code>, and <code>DOUBLE-FLOAT</code> element-type metadata with implementation-observed upgrade aliases plus initial-value and write validation; adjustable character strings and adjustable multidimensional general arrays with alias-preserving <code>aref</code>/<code>row-major-aref</code>/<code>bit</code> updates; bounded displacement through <code>:displaced-to</code> and <code>:displaced-index-offset</code>; bounded <code>MAPHASH</code> and hash-table iterator access. | General compound element types currently use the bounded upgrade-to-<code>T</code> behavior rather than preserving full specialized constraints; multidimensional fill-pointer arrays, displacement/adjustment combinations outside the tested paths, complete sequence edge cases, hash-table mutation during iteration, and standard array semantics remain incomplete. |
| Structures and objects | Basic <code>defstruct</code> support plus classes, instances, generic functions, methods, slot access, and bounded class introspection. | The full MOP, all slot allocation/options, method qualifiers, and standard object-protocol details remain partial. |
| Compiler | Stack bytecode compiler and VM selected by <code>--compiled</code>, executed through <code>eval_compiled</code>/<code>eval_compiled_source</code>. <code>NTH-VALUE</code>, <code>SETF</code> of <code>CAR</code>/<code>CDR</code>/<code>NTH</code>/<code>AREF</code>/<code>SVREF</code>/<code>ROW-MAJOR-AREF</code>/<code>BIT</code>/<code>ELT</code>/<code>CHAR</code>/<code>SCHAR</code>/<code>SUBSEQ</code> on simple symbol places, and <code>PUSH</code>/<code>POP</code>/<code>PUSHNEW</code> with simple symbol places are lowered to native VM instructions. | Generalized-place <code>PUSH</code>/<code>POP</code>/<code>PUSHNEW</code>, keyword-option <code>PUSHNEW</code>, and other compiler paths still use evaluator-backed fallbacks; <code>PUSHNEW</code> retains its evaluator path for <code>:TEST</code>, <code>:TEST-NOT</code>, and <code>:KEY</code> function designators. The compiler covers only the tested language subset and is not an optimizing compiler. |

Both interpreted and compiled execution are covered by the repository's local
tests where the corresponding feature is supported. Passing the test suite
does not establish conformance with other implementations or the full Common Lisp standard.
Compatibility claims should be made only for behavior backed by executable
tests.
